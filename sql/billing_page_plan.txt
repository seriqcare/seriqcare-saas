OVERVIEW
--------
PA Medicaid billing for ODP Waiver (Sandata) and PDA/MA (HHAeXchange) services.
Billing lifecycle:
  Visit completed → EVV Verified → Approved → Claim generated → Submitted → Paid / Denied

Route: /billing

================================================================================
DESIGN DECISIONS (locked for pilot)
================================================================================

1. BILLING RATE SOURCE
   - Add nullable DEFAULT_RATE column to care.service_codes (DECIMAL(10,2) NULL).
   - Pilot estimates: dollars = units * default_rate.
   - Long-term: move to care.fee_schedule with optional authorization-level overrides.
   - SQL: ALTER TABLE care.service_codes ADD default_rate DECIMAL(10,2) NULL;

2. BILLING CLAIMS TABLE
   - Create care.billing_claims via migration (minimal pilot header table).
   - Schema (pilot):
       id              INT IDENTITY PK
       agency_id       INT FK → care.agencies
       claim_date      DATE NOT NULL
       payer           VARCHAR(50)   -- 'sandata' | 'hhax' | 'private'
       status          VARCHAR(30)   -- Draft | Ready | Submitted | Paid | Denied | Voided
       total_units     DECIMAL(10,2)
       total_amount    DECIMAL(10,2)
       created_at      DATETIME2 DEFAULT GETUTCDATE()
       updated_at      DATETIME2 DEFAULT GETUTCDATE()
   - Join table: care.billing_claim_visits (claim_id FK, visit_id FK, units, amount)

3. "READY TO BILL" DEFINITION
   Full rule:
     - approval_status = 'Approved'
     - visit_cancelled = 0
     - evv_status IN ('Verified', 'Adjusted')
     - approved_units > 0 OR billed_units > 0
     - active authorization exists (care.service_authorizations.is_active = 1)
     - service_date BETWEEN authorization start_date AND end_date
     - submission_status is NOT 'Rejected' (i.e. vi.sandata_status != 'Rejected'
       AND vi.hhax_status != 'Rejected')
   MVP fallback (simpler):
     - approval_status = 'Approved'
     - evv_status IN ('Verified', 'Adjusted')

4. UNITS vs DOLLARS
   - Show both.
   - Units: from visit_billing.approved_units (fallback: billed_units).
   - Dollars: COALESCE(approved_units, billed_units) * sc.default_rate.
   - Label as "Estimated" until fee_schedule is implemented.

    - app/billing/page.tsx       → Server component, reads searchParams
    - components/billing-claims-panel.tsx → Client component (queue + history tabs)

  New Backend:
    - GET /api/billing/auth-utilization → Per-client auth used/remaining/expiring
  New Frontend:
    - Auth utilization table page or expanded sidebar widget
    - Expiration alerts surfaced on billing page

PHASE 3 — Claim Generation + Export
  New Backend:
    - GET  /api/billing/claims/{id}    → Claim detail with line items
    - POST /api/billing/claims/export  → 837P flat file or CSV download
  New Frontend:
    - Claim detail modal
    - Export button with format selector (CSV / 837P stub)

PHASE 4 — Denial Management + Remittance
  New DB:
    - care.billing_payments (ERA posting)
  New Backend:
    - POST /api/billing/era-upload  → parse 835 ERA, post payments

  New Frontend:
    - Denial queue panel with reason codes
    - Payment reconciliation view
