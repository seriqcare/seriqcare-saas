2A. AUTHENTICATION
──────────────────
  Protocol:       OAuth 2.0, client credentials flow
  Token endpoint: POST /identity/connect/token
  Body params:    client_id      (issued by HHAeXchange per provider)
                  client_secret  (issued by HHAeXchange per provider)
                  scope          (issued by HHAeXchange per provider)
  Response:       { "access_token": "...", "expires_in": 1800 }
  Token lifetime: 30 minutes; re-authenticate when 401 is received
  Usage:          All API calls must include header:
                  Authorization: Bearer {access_token}
  TLS:            HTTPS with TLS 1.2 minimum required


2B. CAREGIVER RECORD (must be submitted BEFORE visit records)
─────────────────────────────────────────────────────────────
  Endpoint:   POST /api/v{version}/caregivers
  Content-Type: application/json

  Field               Type      Req  Format / Notes
  ──────────────────  ────────  ───  ────────────────────────────────────────
  CaregiverCode       String    REQ  Direct Care Workers Unique Registry ID
                                     if available; otherwise last 5 digits
                                     of caregiver's SSN.
                                     Maps to: care.employees.employee_code
                                     NO prefix required. No "CAREGIVER-" prefix.

  FirstName           String    REQ  Caregiver first name
  LastName            String    REQ  Caregiver last name
  SSN                 String    SIT  Social Security Number (when no Registry ID)
  AgencyTaxId         String    REQ  Agency EIN in format: XX-XXXXXXX
                                     (e.g. "23-1234567")
                                     Maps to: care.agencies.state_provider_id
                                     or care.providers EIN field

  Response:   HTTP 200/201 + TransactionId
  CRITICAL:   Visit submission will be REJECTED if the CaregiverCode
              sent in the visit does not already exist in HHAeXchange.


2C. VISIT RECORD (EVV Submission)
──────────────────────────────────
  Endpoint:   POST /api/v{version}/visits
  Content-Type: application/json
  Max records per request: 100

  Field                     Type      Req  Format / Notes
  ────────────────────────  ────────  ───  ──────────────────────────────────────
  EVVMSID                   String    SIT  Unique visit identifier.
                                           If provided by 3rd party, must be
                                           prefixed with tilde: ~{your_id}
                                           Alphanumeric + dashes/underscores only.
                                           Max length: 64 characters (excl. ~)
                                           Maps to: care.visits.id (formatted)
                                           Example: ~VIS-000123

  AgencyTaxId               String    REQ  EIN format: XX-XXXXXXX
                                           Provider/agency identifier.
                                           NOT the NPI. NOT "PROV-" prefix.
                                           Maps to: care.agencies.state_provider_id

  CaregiverCode             String    REQ  Same value as used in Caregiver record.
                                           Registry ID or last-5 SSN.
                                           Maps to: care.employees.employee_code

  MedicaidNumber            String    REQ  Client's PA Medicaid ID (state-assigned).
                                           No fixed prefix required.
                                           Maps to: care.clients.medicaid_id

  ProcedureCode             String    REQ  HCPCS code — standard 5-character format.
                                           1 letter + 4 alphanumeric chars.
                                           Examples: W7060, T1019, S5125, H2015
                                           NOT a 3-digit number.
                                           Maps to: care.service_codes.hcpcs_code

  PayerId                   String    REQ  MCO/Payer numeric code.
                                           Examples:
                                             17470 = AmeriHealth Caritas PA
                                             28242 = UPMC Home Health
                                           Maps to: payer/MCO on service auth

  ScheduleId                String    REQ  Schedule identifier.
                                           Maps to: care.schedules.id (formatted)

  ScheduleStartTime         DateTime  REQ  UTC format: YYYY-MM-DDTHH:MM:SSZ
                                           Scheduled start of visit window.
                                           Maps to: care.schedules.scheduled_start

  ScheduleEndTime           DateTime  REQ  UTC format: YYYY-MM-DDTHH:MM:SSZ
                                           Scheduled end of visit window.
                                           Maps to: care.schedules.scheduled_end

  ClockInDatetime           DateTime  SIT  UTC format: YYYY-MM-DDTHH:MM:SSZ
                                           Actual EVV clock-in timestamp.
                                           Maps to: care.visit_evv.call_in_datetime
                                           Required if ClockOutDatetime is provided.

  ClockOutDatetime          DateTime  SIT  UTC format: YYYY-MM-DDTHH:MM:SSZ
                                           Actual EVV clock-out timestamp.
                                           Maps to: care.visit_evv.call_out_datetime
                                           If omitted, visit is unconfirmed.

  ClockInServiceLocationType  String  REQ  Location type code at clock-in.
                                           (e.g. Home, Community — see code table)
                                           Maps to: care.visit_evv location fields

  ClockInServiceLocationAddress String REQ  Address at clock-in.
                                            Maps to: care.clients address fields

  ClockOutServiceLocationType String  REQ  Location type code at clock-out.

  ClockOutServiceLocationAddress String REQ Address at clock-out.

  InvoiceNumber             String    SIT  Required for billed visits.
                                           Alphanumeric claim/invoice reference.
                                           Maps to: billing claim number

  MissedVisit               Boolean   OPT  true if visit was not completed.

  MissedVisitReasonCode     String    SIT  Required if MissedVisit = true.
                                           Codes 508-525 (see PA code table).

  MissedVisitActionCode     String    SIT  Required if MissedVisit = true.

  VisitEditReasonCode       String    SIT  Required when updating existing visit.
                                           Codes 100-123 (see PA code table).

  DutyCodes                 Array     OPT  List of task/duty codes completed.
                                           Codes 115-203 (see PA code table).
                                           Example: ["115", "120", "135"]

  OVERNIGHT VISIT RULE:
    If a visit crosses midnight, it MUST be split into two separate records:
      Record 1: original date, start time → 23:59:59
      Record 2: next date, 00:00:00 → actual end time
    Both records share the same ScheduleId.

  SECTION 6 — SUMMARY: WHAT THE SIMULATOR IS vs WHAT IT SHOULD BE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  The current simulator was built with fictional simplified IDs ("PROV-",
  "CAREGIVER-", "PATIENT-", 3-digit service codes) that do not match the
  real Pennsylvania HHAeXchange field formats.

  The real PA HHAeXchange spec requires:
    - Agency identified by EIN (Tax ID), not a custom prefix
    - Caregivers identified by Direct Care Worker Registry ID or SSN-5
    - Clients identified by PA Medicaid Number
    - Service codes as full HCPCS procedure codes (5-char alphanumeric)
    - OAuth 2.0 bearer token authentication on every request
    - Caregiver record must be registered before visit record
    - Full ISO 8601 UTC datetimes for all timestamps
    - EVVMSID returned by HHAeXchange after each accepted visit
    - External EVVMSID prefixed with ~ tilde character
    - Overnight visits must be split at midnight

  After applying all fixes above, the simulator will:
    1. Accept the same field names and formats as real HHAeXchange PA
    2. Validate using real business rules (EIN format, HCPCS codes, etc.)
    3. Require (simulated) OAuth authentication
    4. Enforce caregiver-first submission order
    5. Return EVVMSID values that SeriqCare can store and use for updates
    6. Allow SeriqCare backend hhax.py to be written once and work for
       both the simulator (HHAX_MODE=simulate) and production (HHAX_MODE=live)
       with zero code changes
